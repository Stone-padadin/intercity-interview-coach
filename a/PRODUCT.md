# Product

<!-- impeccable:product-schema 1 -->

## Platform
web

## Stack
Static HTML, CSS and JavaScript; Python standard-library local server reusing C's Notes/Lab services. Measurements, notes, video metadata and A's experiment/review metadata share one SQLite file. Node.js runs browser-store regression tests; legacy interview dependencies remain locked for historical regression only.

## Users
Electronic, automation and embedded-systems learners recording and troubleshooting real bench experiments.

## Product Purpose
Keep confirmed measurements and experimental conditions together so a learner can compare retests and choose the next verification. The intended full product adds spoken measurements and historical visual evidence; that integration is not complete.

## Capabilities and Constraints
Implemented in software: experiment creation and switching, manual and final-ASR measurement drafts, explicit confirmation, server persistence, experiment isolation, linked retests, reversible retraction, manual review and Markdown export. C's capture/video page shares the same experiment ID and database. Legacy browser records have an explicit import action that preserves their IDs and original browser data.

Pending real acceptance: developer-board spoken measurement through B's bridge, actual experiment videos and model cases, device output and shared platform context. Ten-minute rolling history and region selection remain unimplemented. No automatic instrumentation, safety certification, diagnostic accuracy or learning-outcome claims. Opening the service does not activate the camera, serial port, audio or a paid model request.

## Brand Commitments
Quiet, readable and grounded in real bench work. Warm neutral surfaces, deep green emphasis, visible record provenance. Separate observations from hypotheses and actual capabilities from planned integration.
