# PID 11920 试用验证 · 2026-11-01

本次验证对象为用户连接的 ESP32-S3 开发板。用户明确要求保留原 PID 11919，先备份，再让同一块板试用 PID 11920。此记录更新硬件试用结果，不把此前的软件测试当作实物验收。

## 已验证

- 读取切换前完整 16 MB Flash，并与实物全量校验一致。备份、配置和恢复程序仅保存在本机忽略目录；备份时旧网络已经不可用，原快照处于等待配网状态，恢复后可能仍需配网。
- 试用应用写入原先空闲的 OTA1；启动选择保留原 OTA0 选择扇区。后续应用更新均只写 OTA1，原 PID 11919 应用再次与备份校验一致。试用配网和注册会更新本机配置，完整恢复应使用完整备份，不能仅切启动槽便声称所有状态恢复。云端产品未删除。
- 使用授权账号下 PID 11920 的产品身份构建。B 实验桥开启，SPI 视觉和灯圈关闭；没有修改团队原 SDK 工作区。隔离副本构建、镜像检查及实物写入回读校验通过。
- 当前现场网络采用 WPA-Personal。仅在本次私有候选中，为用户指定网络调整认证筛选兼容性，随后实际取得 IP 并连上云端。此设置不是面向所有网络的通用降级方案；个人网络标识和密码不进入仓库。
- 电脑配好 Wi-Fi 后，设备在线仍未完成用户小程序账号绑定。使用既有 SDK 的本地重新配网接口，用户在官方“灵机一动AI”小程序重新添加新产品，并确认显示在线。
- 绑定后观察到远端 AI 加入、语音识别、回复文本及播放开始事件；用户确认听到完整回答。实际说“你好小灵”时收到声学唤醒事件，因此该唤醒词在本板已实测有效。

## 证据边界与待完成

首次语音诊断由电脑的本机入口触发，复用了正常鉴权和启动路径；该次触发本身不是声学唤醒证据。后续独立观察到了声学唤醒事件和用户听到的回答，但尚未专门验收冷启动后完全由唤醒词建立新会话。

55 秒绑定后观察窗口内有两次 Agora 错误码 130。固定 SDK 头文件将其定义为 `ERR_DATA_STREAM_TIME_OUT`；随后仍观察到识别和回复播放。本次不判断根因，也不宣称长时间稳定性通过。

基本语音通路通过不等于实验助教完整产品通过。以下仍待验证：当前应答是否使用目标已发布 Agent 的角色和工作流、真实语音记录进入正式实验服务、电脑/网页与设备共享实验上下文、知识检索实际命中、提醒实物输出、断网恢复及长时间运行。原始语音、凭据、固件、配置、Flash/NVS 和个人网络信息均未提交 Git。
