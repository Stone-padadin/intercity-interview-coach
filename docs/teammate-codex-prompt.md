## 项目背景和目标

项目名：难开口陪练。面向嵌入式开发实习/校招的面试练习，核心困难是面对追问或反对时接不住。

目标闭环：上传简历 → 用户确认一个项目 → AI 语音面试与追问 → 根据实际回答反馈 → 重练。视觉是辅助反馈，优先保证一次完整面试稳定运行。

## 分支与依赖规则

- 执行 git fetch origin 后，从最新 origin/main 创建 feat/<我的GitHub用户名>-<任务简称>；修复用 fix/。已有同一任务分支就检查后继续使用。
- **若 PR #1 已合并：**正常基于最新 main 开发，PR 目标为 main。
- **若 PR #1 尚未合并：**仍先从最新 origin/main 建我的任务分支。若本次任务依赖 C 代码/公共文档，把远程 feat/stone-padadin-c-vision-bootstrap 合并到“我的任务分支”，只在自己的分支整合依赖；不是合入 main。发现无法判断的冲突先报告双方意图，保留工作。
- 依赖未合并的交接分支时，PR 暂以该交接分支为 base，说明依赖 PR #1，避免把整套 C 代码误报成自己的改动；PR #1 经团队审阅合并后，再同步 main 并调整 PR base。
- 若任务完全不依赖交接实现，可独立开发并向 main 提 PR，但不要复制一份相互冲突的公共约定。
- 不直接推送或合并 main，不强推，不自行批准或合并任何团队 PR。依赖分支变更后重新检查影响，不把本地整合等同于团队已批准。

## 当前代码和证据边界

- C 已提交实时视觉、标定/去抖、USB本地预览、纯C与Python测试、固定SDK补丁及接入脚本。
- A/B/D 目录目前主要是接入说明，不代表对应产品功能已实现。
- 厂商 SDK 不在仓库内：参照 c/firmware/upstream.json 和 c/README.md 获取固定版本，用 scripts/prepare_sdk.py 接入。该脚本拒绝覆盖有修改的SDK；不要绕过保护。
- 原开发机上的SDK、Conda环境、工具链和设备不在队友电脑上。新机须检查依赖，不使用作者机器的绝对路径。
- 硬件采用比赛已确认的板卡与器件，以 docs/hardware.md 和原理图为依据。GPIO4/8 有外设冲突风险；未知引脚、电压、供电或接口不要猜测。
- 视觉使用上游 YOLO11n-pose 关键点；首版固定机位并显式建立个人正坐基准，只尝试判断持续肩线侧倾。相机移动需重新标定。
- 旧SDK的 status/error 只是调试标签，不能直接用于提醒；接入时核对 calibrated_raw、stable_state 和 valid。未知、未标定和过期不能当作表现差。
- 推理历史约每2秒一次，不能承诺可靠检测快速抖动，也不能由姿态推断心理紧张或医学状态。
- C 到网页/Agent 的正式网络API尚未实现，需共同确认；诊断串口及本机预览不是已经批准的产品接口。
- 3D打印结构尚无验收通过的CAD/STL，转接板尺寸和装配仍需实测。
