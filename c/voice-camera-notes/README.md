# 语音与照片随手记 · C 侧联动原型

用户做实验时，说“你好小灵，记一下，……”后，电脑将完整口述与接收附近的一张照片关联，显示待确认卡片；核对或修正文字后，点击确认保存。记录功能验证免打字的价值；新增独立的静音看图问答入口，通过本机后端调用用户配置的视觉模型。模型结果不自动当作实测或接线诊断结论。

本模块在 C 目录独立实现，不覆盖 A 的网页/数据库或 B 的源码，不修改公共协议。它实现 B 的本地桥接提案所需的兼容接收端；不是声称 A 已确认或接入了该接口。存储是此原型自己的本机 SQLite，尚未并入正式实验服务。

## 运行

Python 3.11+，OpenCV 与 pyserial。建议独立虚拟环境：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py --bridge-source <已审阅B工作区>/b/lab/bridge.py --serial-port COM7
```

关闭其他相机采集器和串口监视器。默认监听 `127.0.0.1:8768`，浏览器打开 `http://127.0.0.1:8768`。页面点击“开启摄像头”，确认操作区完整入镜；电脑内置相机默认索引 0，可用 `--camera-index` 更换。数据默认在模块下 `.local/`；后续重启沿用同一目录，页面刷新可看到已存记录。关闭摄像头会释放相机，已有照片保留。退出整个程序使用 Ctrl+C，程序会结束自己启动的桥接子进程，不重启/重刷板子或清除配网。

`--bridge-source` 复用 B 的 [PR #10](https://github.com/Stone-padadin/intercity-interview-coach/pull/10) 实现，本次本机来源为其提交 `697de5683ca84d219180ea4af5e241a653e56a67`。依赖支持 `BLAB1` 实验事件的已审阅固件；本模块不提供固件或产品密钥。省略此参数仅可查看页面，不能宣称语音已接通。

应用为这轮试用生成并持久保存实验归属 ID，唯一串口桥接执行绑定、时钟同步及 record 模式请求。须收到对应模式回执才显示就绪；原生 Agent 会话不会因为本地绑定而清空历史。不要将本地实验 ID 当平台 Agent ID。

## 实际行为与边界

- 只有 `asr.final`、本人报告、完整未截断且以“记一下”命令开头的短句才创建卡片。“不要记一下”、普通问答和模型输出不会触发拍照；“记一下”单独一句缺少内容，不创建空白记录。
- 只取实时采集器中的最新 JPEG，不另开第二个摄像头。图像帧主机接收时间距拍照请求不得超过 2 秒。转写进入本地桥接后超过 5 秒才送达本模块，或不处于 record 模式时，不会拿现在的照片冒充旧事件。
- 记录明确标注转写接收时间、图像主机接收时间、两者偏差及设备时钟估计（如有）。这些都不是开口时刻或传感器曝光时间。云端识别延迟尚未补偿；用户必须核对画面。
- 先在本机落盘再确认接收，同一事件 ID 的传输重试不重复拍照。同 ID 不同正文拒绝覆盖。SDK 没有唯一语句 ID；不同事件 ID 的重复识别仍可能形成多条卡片，不能宣传语义级自动去重。
- 拍照失败仍保留未确认口述及失败提示，不生成假照片，也不允许确认完整图文记录。确认前再次校验照片文件存在且摘要一致。确认保留原始口述、修正文本、来源及用户点击时间；数值不会变成仪器实测。
- 原生 Agent 的普通回答不代表本机已保存，也未注入此处记录。首版以页面状态为实际回执；设备原生对话、电脑结果播报、语音确认及共享上下文仍是独立验收项。
- 未启用连续录像。预览帧只驻留内存，命令触发的照片才进入记录目录。B 桥接为了可靠投递，会在自己的私有 SQLite 缓存原始转写/设备事件；不能把“本模块不保存非命令口述正文”扩大为整条链路从不缓存语音文字。原生语音仍使用既有云服务，默认不上传照片；只有明确点击看图发送操作后，才把本次照片和问题（分析已有记录时还包括该条口述）交给配置的模型服务。

## 连续预览

原型初版浏览器每 350 ms 请求一张 JPEG，显示上限约 2.86 fps；实测 5 秒 14 次刷新，即 2.8 fps。现改为一条 MJPEG 连续响应，等待新帧后推送；慢客户端跳过旧帧，不建立长队列。采集请求 1280×720、30 fps、MJPG 传输，输出 JPEG 质量参数保持 88，采集任务最高按 30 fps 运行。真实可达帧率由相机、曝光与主机负载决定；页面显示近 5 秒实测采集率，不将驱动请求值当实际值。

2026-11-01 本机真实相机 10 秒检查：连续传输收到 **292 个不同序号帧，29.1 fps**，浏览器图像为 **1280×720**，同期采集状态约 29 fps；开发板桥接和 record 模式回执仍正常。该检查未保存视频或测试图像。传输率不是浏览器逐帧呈现率的仪器测量，也不是长时性能或完整语音拍照验收。

## 本机接口

- B 兼容端点：`POST /api/lab/device-events`、`GET /api/lab/device-commands?experiment_id=...`，使用 `b.lab.v1` / `b.lab.command.v1`。原型只请求 record 模式，不下发播报或其他设备动作。
- 页面：`GET /api/state`、`GET /api/stream`（MJPEG）、`GET /api/preview`（单帧）、`GET /photos/<摘要>.jpg`。
- 相机控制：`POST /api/camera/start`、`POST /api/camera/stop`，JSON `{}`。
- 明确确认：`POST /api/confirm`，JSON `{id,text,user_confirmed:true}`。

只允许 loopback 监听及匹配本机 Host/Origin 的访问，无 CORS 放开，不支持公网部署或多用户隔离。不在浏览器或配置样例放产品凭据。原始照片、数据库、桥接队列、环境、测试媒体和构建产物全部留在 ignored `.local/`，不要提交 Git。

## 自建图片通道 · 当前实现

路径：电脑摄像头最新 JPEG／已有记录的校验照片 → 本机 `POST /api/vision/ask` → 模型服务 `/chat/completions` → 页面文字结果。以标准 `image_url` Base64 图片加文本发送；不依赖灵机一动拍照插件。灵机仍承担原有语音链路，本模块不读取其内部模型或插件密钥。

依据：[百炼官方视觉理解文档](https://help.aliyun.com/en/model-studio/vision)。示例提供 Qwen 配置；其他提供商须自行核对是否兼容相同请求和响应格式。服务域名、地域、工作空间、模型访问权限和账单以用户自己账户为准，不自动创建账户或开通计费。

将 `vision-config.example.json` 复制到本模块 `.local/vision-config.json`，在本机填入 `base_url`、`model` 和 `api_key`。地址填写到 `/v1` 层级，不含 `/chat/completions`；示例中的 WorkspaceId 须替换。使用允许应用后端调用的服务授权，不复用仅限个人交互工具的套餐凭据。配置文件已被 `.local/` 忽略；不要将密钥贴到聊天、网页代码或 Git。后端每次读取配置，填写后无需重启。

静音测试可以不传 `--bridge-source`，这时不会打开串口或向板子下指令。页面输入自由问题、勾选照片发送许可，再点击“发送当前画面并提问”；或点击某条记录的“发送这条照片并提问”。后者发送该条已存照片及口述，不会拿当前帧替换历史照片。相机不是 USB 串口板载摄像头，当前图像来源仍为电脑摄像头。

只发送一次选定图片，不连续上传视频，不自动语音播报；不自动上传语音触发的记录。模型回答单独显示为 AI 生成，不覆盖口述，不自动确认保存。目前为单次图文问答，没有多轮记忆、工具执行、语音问答路由或完整 Agent 循环。当前画面问答不保存照片或答案，刷新页面会清空回答；已有记录仍按原路径持久保存。

传输约束：HTTPS，禁止重定向转发授权，单图上限 8 MB，请求超时 35 秒，仅允许一个在途模型请求，无自动计费重试。页面不返回密钥或原始服务错误；无有效配置时直接提示未配置，不伪造分析。

新增 5 项模拟服务测试，与原有 13 项合计 **18 项通过**，涵盖实际图片字节与问题封装、HTTP 发送许可、历史图完整性、配置缺失、忙碌、无效响应、授权失败和网络超时。浏览器页面入口另行检查。**未完成真实模型识图**：用户当前没有独立视觉 API 授权。填写有效授权后，先用随机数字和色块纸张验证，数字答案只能来自图像；通过后再试实验场景。模拟返回成功不能替代该验收。
