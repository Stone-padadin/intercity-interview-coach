### 资料进入分析

1. 使用 `c/voice-camera-notes/` 的现有页面导入有授权的实验视频，并定位实际画面。
2. D 根据本次问题选择知识库相关短节，核对器件型号、资料版本与来源；不要直接把全部知识库塞入输入框。
3. 将片段填入“实验资料”栏。保留文件名、章节及来源 URL，总长度不超过 4000 个字符。资料中的范例数值不能填成现场测量。
4. 用户明确同意发送后，现有 `POST /api/demo/analyze` 将 `materials` 作为背景附加到模型问题中。`media_id` 和时间必须来自实际导入片段。
5. 人工核对结果引用和不确定性。仅保存模型输出或显示结果不等于故障已经定位、测量已确认或操作已执行。

当前没有自由操作问答的检索 API，也没有自动从此目录读取知识的实现。这是可人工复现的资料接入方法，后续自动化需 A/C/D 共同确定接口。

### 三种模式与 D 的边界

| 当前模式 | 现有行为 | D 对接要求 |
|---|---|---|
| safety | 对当前单帧检查限定焊接线缆风险；结果校验为 risk/clear/unknown | 保留原响应结构；clear 只表示该目标未见风险，unknown 不能转成 clear |
| wiring | 单帧观察加限定 LED 核对模板 | 资料库覆盖更多器件不代表模板已经支持任意接线；型号、极性或阻值不清时补证 |
| history | 最多三张历史画面和已确认口述参与分析 | 分开引用画面时间、用户口述与资料来源；候选原因不是定论 |

`d/knowledge-base/embedded-safety/visual-event-schema.json` 是另一份事件草案，包含 V01 至 V10、等级和置信度；当前网页 `alert` 并不消费这些字段。不要将草案直接替换当前响应，或仅凭 risk/clear 推造等级、类别与置信度。

### 语音测量

沿用最终转写、待确认草稿、补字段、用户明确确认、刷新回读流程。`73.3 mV` 与 `0.0733 V` 可作同值换算说明，但必须保留原口述和单位；没有确认就不能把草稿送作已确认测量。

资料文本不能产生真实 `event_id`、测量回执或设备在线状态。电脑分析尚未接回开发板播报；播报成功也不能单独证明设备 Agent 共享了电脑上下文。

## 本机复现

使用 Python 3.11 或更新版本。在仓库根目录创建项目环境并安装已有依赖：

```powershell
py -3.13 -m venv .venv
.venv\Scripts\python.exe -m pip install -r c\voice-camera-notes\requirements.txt
cd c\voice-camera-notes
..\..\.venv\Scripts\python.exe -m unittest -v test_app test_vision test_lab
..\..\.venv\Scripts\python.exe app.py --port 8771
```

打开 `http://127.0.0.1:8771/`。选用本机已安装的 Python 版本；端口占用时换空闲端口。默认不传 `--bridge-source`，不连接串口；相机由用户显式开启。API Key 按 C 模块说明只保存在忽略的 `.local/`，本次没有配置密钥或发起计费模型请求。

此服务限制本机 Host/Origin，不能直接作为公网部署方案。B 桥接需以 PR #10 实际审阅版本配合，并保持单一串口读取者。
