# AI 实验台助教 · INTERCITY HACK

面向电子、自动化与嵌入式学习者的实验助教：**口述测量并确认保存，遇到问题时回看刚才的操作，再根据证据提出下一项验证。**

本仓库从“难开口面试陪练”转向这一方向，复用语音、网页与视觉代码。仓库 URL 暂沿用 `intercity-interview-coach`；旧模块中的面试页面和示例不代表新产品已经完成。

## 目标使用过程

1. 开始一个实验，确认电路背景、测量点与检查清单。
2. 用户口述测量，系统补问位置、数值、单位与条件，确认后保存。
3. USB 相机记录实验台；用户提出问题并在截图上圈选位置。
4. 根据历史片段和已确认测量，给出有时间或事件引用的观察、候选原因，以及一项优先验证。
5. 用户复测，更新记录并导出可追溯的实验复盘。

先跑通一条真实测量和 30–60 秒证据片段，再实现最近 10 分钟的滚动回溯。护目镜识别和手指定位是后续能力，当前姿态模型不具备这些功能。

## 设备、平台和电脑的职责

| 部分 | 职责 | 当前边界 |
|---|---|---|
| 开发板＋灵机平台 | 原生语音对话、设备能力、RGB 与状态反馈 | 用户已确认真实两轮对话；新角色、平台控制与实验桥接待验收 |
| 板端 SPI 相机 | 固定机位下的人体姿态辅助 | 已有标定与肩线侧倾代码；本轮没有采到姿态数据，不计为复验通过 |
| 电脑侧 USB 相机 | 实验台录像与证据截图 | 电脑相机已实录720p/15fps短片段并完整解码；机位裁切、遮挡仍需调整，独立外接设备未确认 |
| 电脑服务与网页 | 测量确认、缓存、时间线、圈选、分析与复盘 | 需要改造现有面试页面，尚无新产品闭环验收 |

电脑是系统的一部分。硬件价值来自真实实验的语音交互与现场观测；“必须使用硬件”本身不是需求验证。平台对话与电脑证据是否共享上下文，需要实际测试。

## 快速检查

需要 Python 3.11 和 C11 编译器；软件测试仅使用 Python 标准库。

```sh
python scripts/test_c.py
```

Windows 已安装 Visual Studio Build Tools 时：

```bat
scripts\Test-C.cmd
```

被动读取当前设备数值诊断，需要 `pyserial`，并确保没有其他进程占用串口：

```sh
python c/tools/cvision/observe_device.py --port COM7 --seconds 45 --experiment-id lab-check
```

端口按本机实际调整。工具不发送指令、不保存原始串口文本；输出留在忽略的 `.local/c-observations/`。它不替代真人测试，也不是正式实验事件桥接。固件接入与预览见 [C 说明](c/README.md)。

厂商 SDK、设备身份、密钥、原始照片、音视频和串口日志不进入 Git。软件通过不等于整机通过。
