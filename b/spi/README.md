# SPI姿态检测与平台语音控制 · PID 11919

这是一份独立候选实现。设备端接通“明确开始→用户就位后标定→持续肩线侧倾检测→暂停/恢复/停止→状态回报”，平台走官方设备IoT控制插件。保留原11919产品身份的构建入口；当前没有完成账号内物模型配置、正式身份候选构建、刷写或实机验收。

## 已实现

- `b_spi_workflow.c`：默认关闭、独立检测阶段、显式标定、采集中重复命令不清零、断线撤销授权；恢复仅接受恢复后的新帧。无效、遮挡、过期或乱序捕获均不输出有效姿态。
- `b_spi_runtime.c`：平台属性→B既有单一任务队列→实际状态迁移→影子属性上报；保持音量等既有属性处理。LED状态使用独立SPI授权，不通过假切面试阶段来获得橙灯。物理LED仍默认编译关闭。
- C live入口：允许暂停新的推理提交，丢弃暂停/恢复前仍在计算的结果，恢复时重建去抖；保留RAM标定基准。暂停不切断相机供电或相机流。已有C诊断profile默认行为保留；只有SPI工作流候选在相机启动前默认暂停推理。
- 独立安装器：严格检查已评审B/C源文件指纹和插入位置，只允许已标记的临时SDK副本；写入前完成全部验证并备份目标。视觉或B运行层初始化失败时继续语音/联网启动；仍须验证资源不足时音频本身能否成功初始化。
- 平台场景、属性、枚举和回复约束见[语音场景配置](platform/语音场景配置.md)。该文件是配置规范，不是已发布平台工作流。

## 复现顺序

1. 从已有C+B整合SDK复制新的**英文短路径**候选，保留原SDK、原镜像和NVS。不要用已有队友修改的SDK直接覆盖。

```powershell
python b/spi/stage.py --source-sdk <已评审C+B-SDK> --target <新的临时目录>/sdk
```

2. 登录灵机平台，在PID11919产品保留既有功能，新增独立SPI服务与六个属性。将平台真实分配的服务/属性ID填入`platform/11919-property-mapping.example.json`的本机副本，存入ignored `.local/`。不要猜编号，不占用音量服务。只有属性映射JSON应送入`--mapping`，不是含SECRET的产品身份文件。

```powershell
python b/spi/prepare.py --sdk <候选SDK> --mapping .local/spi11919-mapping.json --check
python b/spi/prepare.py --sdk <候选SDK> --mapping .local/spi11919-mapping.json
```

没有账号映射时可省略`--mapping`完成离线编译检查；此时固件明确关闭平台SPI属性分发，不能把它当已完成云端集成。

3. 本机产品身份JSON格式为`{"pid":11919,"secret":"实际产品密钥"}`，只存ignored `.local/`。使用现成ESP-IDF工具链构建；工具仅在临时候选头文件中注入身份，不把SECRET放进命令行。构建工具支持本机既有的`idf-python`、`idf-tools`布局，不安装或升级工具链。

```powershell
python b/spi/build.py --sdk <候选SDK> --output <新的构建目录> --tools-root <现有工具链根目录> --identity .local/product11919.json
```

不提供`--identity`时只构建PID0/UNCONFIGURED的离线验证镜像，**不能烧入作为11919产品使用**。LED和实验串口桥在此最小候选中关闭，未声称保留或验收实验记录桥；音频/云语音代码保留。所有构建产物、SDK配置和完整日志仅存本机，不上传。

`--rebuild`只允许复用带本工具验证清单的候选输出，且不能切换产品身份。SDK源文件改变后须重新验证；不可复用旧镜像代替新版本。

4. 本仓库工具不包含SPI候选烧录命令。实际部署前核对当前设备身份、独占窗口、完整恢复备份和分区；保存当前可用语音版本。不能套用IDF自动打印的全量flash命令覆盖原OTA选择、NVS或模型。SDK初始化失败时的降级不代表已证明语音/SPI并发资源充足。

## 本地诊断与证据

只有关闭其他串口读取者、且已确认候选正在运行后，才使用以下诊断命令：`b spi start/calibrate/pause/resume/stop/query`。本地命令经同一B任务执行，但不是平台实际调用证据。

SPI状态使用`SPI_STATUS mode=... posture=... cal=... samples=... result=... frames=...`；原`b status`的面试阶段和pose字段不是本工作流状态，不能混用。模型诊断仍为`CPOSE`和`CCAL`。只分享统计，原始日志留本机。

只有READY基准及新鲜、有效、单人、无模型错误、几何和稳定状态已知的帧可以产生pose=1/2。超过6000ms后为未知；正坐/侧倾阈值及十个连续标定样本沿用C实现，未为演示调低。当前算法只判断肩线相对基准的持续侧倾，不等于驼背/前倾或危险识别。

原生属性命令没有应用层request_id：开始/暂停/恢复/停止按状态幂等，采集中重复标定不重置；但标定完成后再收到同值标定命令会重新标定，不能声称跨网络重放的严格一次执行。连接恢复后需要用户重新开始；平台若只能证明下发，请回答“已发送请求”，不能把它当设备已完成操作。
