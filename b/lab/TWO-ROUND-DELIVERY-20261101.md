# PID 11919 · 两轮硬件语音交付 · 2026-11-01

本轮目标是用户指定的产品 **PID 11919**。不把产品编号当成平台 Agent ID；平台内部 Agent ID 与版本仍由 D 在产品详情核对。本轮只验原生硬件语音对话，未接摄像头，不依赖网页或视频分析。

- 起初 COM7 板子的启动日志实际为 PID 11920，与用户指定目标不同。保存当前待覆盖范围的私密备份、核对分区后，切回已验证的 PID 11919 应用；没有更改云端 Agent 提示词或版本。
- 候选来自 B 的语音上传修复版本（源提交 `697de56`）。本机产品配置、CMake 参数及云组件编译参数均为 11919，密钥匹配检查通过，密钥不进入 Git。
- 应用为 1,820,144 字节，SHA-256 `22ee18c88708bb76566809bf5c525fe06811c0cb5f309d0a314919b65b445f19`。只写应用和 OTA 启动选择区；烧录没有写 bootloader、分区表、NVS 或模型。
- 烧录后独立重启取证：启动 PID=11919，出现获取 IP、实际 cloud connected=1，状态由 online=0 变为 online=1；该观察窗口没有 panic。保留当时已保存的 Wi-Fi；本轮日志未独立打印 SSID，不能仅据此核定接入点名称。

## 两轮结果

以下是测试主题和用户回报的回答大意，不是模型输出的逐字稿，也不是实际电路测量结果。

| 轮次 | 口头测试主题 | 用户确认听到的回答大意 | 设备证据 |
| --- | --- | --- | --- |
| 1 | 假设低压 LED 电路的灯不亮，先询问排查信息 | 询问电源是否开启、电压表是否有读数 | final ASR 回调、音频下行首帧、播放开始 |
| 2 | 尚未确认电源与读数，能否直接判断 LED 损坏 | 要求先查看电压表和电源数据，再判断是否存在接线问题 | final ASR 回调、再次播放开始；用户确认听到回答 |

**验收结果：两轮原生硬件语音交互通过。**依据为设备转写/播放事件与用户两次听感反馈相互对应。第二轮回应承接了电源、读数和接线排查主题；这只支持该限定场景，不推导为通用推理或诊断准确率通过。

取证使用独立实验 ID `delivery_380acb4df4cf451e`。本轮记录中 final ASR 回调数可能多于两条，不能把回调数当作用户轮数或独立识别准确率。本轮没有捕获 `tts.final` 回调，因此没有以 TTS 逐字稿复核回答；回复大意依据用户反馈。下行“首帧”事件也不要求每轮重现。

取证结束后已停止电脑日志采集、关闭详细音频 trace，并释放 COM7；最后将设备恢复为 `record`，收到匹配的 `mode_set` 回执和 online=1，供下一次语音展示。

3. 唤醒“你好小灵”，用上表两类口头问题连续测试；分别检查 final ASR、播放事件与实际回答。
